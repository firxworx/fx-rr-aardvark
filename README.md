# fx-rr-aardvark

A basic pnpm workspace (monorepo) boilerplate with react-router v8 framework mode (SSR) for deployment to Cloudflare Workers.

With biome for lint/format and pnpm catalog + syncpack for dependency version management.

Preview: https://aardvark-web.bitcurve.workers.dev/

## Features

A lightweight project starter stack intended to save time but not go too far and get in the way.

App:

- react-router v8 for cloudflare workers (stock worker entrypoint; no custom server)
- [nuqs](https://nuqs.dev/) for working with search/query params as state with strong typing and validation
- CSP (strict nonce-based policy via `@workspace/core/csp`) with nonce generation in worker entrypoint
- security headers (HSTS, referrer/permissions policies, etc.) via `@workspace/core/security-headers` plus `public/_headers` for static assets
- theme (light/dark/system) with route/action, hooks, and an example theme selector component

Styling:

- [base-ui](https://base-ui.com/) configuration with recommendations from docs (`CSPProvider`, root element, body classes, etc.)
- tailwindcss v4 configured to support _both_ coss-ui _and_ shadcn/ui component registries
- custom `typeset` class generated by https://ui.shadcn.com/typeset for out-of-the-box typography
- variable fonts (self-hosted) provided by fontsource.org (Inter) with metric-matched fallbacks via fontaine; mono uses the system font stack (tailwind default)

Light/Dark:

- css `light-dark()` and `color-scheme` for automatic system theme detection and switching
- custom tailwind `dark` variant to support `light-dark()` in tailwind classes

## Styling

The palette tokens of [coss-ui](https://coss.com/ui/docs) and [shadcn/ui](https://ui.shadcn.com/) are merged into a single set of tokens and separate `:root` (light) and `.dark` (dark) colors are combined into single `light-dark()` definitions under `:root`.

As coss-ui was inspired by shadcn/ui the tokens are almost completely compatible.

Refer to [docs/styling.md](./docs/styling.md) for key details on styling, tokens, and light/dark theme.

## Layout

See `pnpm-workspace.yaml` for workspace configuration and pnpm catalog.

- `apps`
  - `web/`
    - `app/` - react-router app directory (routes, etc).
    - `worker/` - cloudflare worker entrypoint
- `packages/`
  - `core/` - shared utilities
  - `ui/` - shared UI components and global styles
- `tooling/`
  - `tooling/tsconfig` shared typescript configs

## Commands

From workspace root:

```bash
pnpm dev              # dev server
pnpm typegen          # generate types (wrangler types)
pnpm typecheck        # typecheck (tsc)
pnpm test             # run tests (vitest)
pnpm check            # biome lint/format
pnpm check:fix        # biome lint/format (fix/write mode)
pnpm preflight        # biome check:fix + typecheck + build
pnpm dlx knip         # audit dependencies and exports with knip
pnpm syncpack list    # analyze dependency versions
pnpm syncpack fix     # analyze dependency versions (fix/write mode)
```

Agent tooling `pnpm shot` script takes a screenshot of the dev server for visual checks (dev server must be running).
See `apps/web/scripts/shot.ts` for details.

For convenience run `pnpm kill:port <port>` to kill a process running on a given port.
This is handy if the dev server is not responding or if it was left running in the background by an agent.

## Tips

Use pnpm catalog (`pnpm-workspace.yaml`) for dependency versions alongside complementary `syncpack` to enforce consistent version policy across the workspace.

Consider adding `@commitlint/cli` + `@commitlint/config-conventional` to enforce commit message conventions;
use alongside tooling such as `lefthook` or `husky` to run commitlint on commit.
